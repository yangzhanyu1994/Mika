# 智能场景（第一阶段）

在侧栏进入智能场景。现有定时任务保留原入口，也可从场景页进入。蓝牙场景可选择已配对设备、连接或断开事件、等待秒数和执行内容。默认等待 60 秒；等待期间状态反转时取消该次触发。场景通过现有任务调度与通知机制执行，上次执行入口打开对应对话，并不代表任务已经成功。

启用场景需要允许附近设备访问；监听使用前台服务和常驻通知。系统蓝牙关闭、权限撤销、用户完全退出、系统停止服务或设备重启后未能恢复服务时，场景不能保证触发。重新打开 Mika 会尝试恢复监听。系统电池策略、精确闹钟权限和后台限制也可能影响执行时效，需要在真实设备上验证。监听停止期间的事件不会补发。Wi-Fi 场景支持指定网络名及连接/断开；需要精确位置权限才能读取网络名。位置场景支持当前位置或手动坐标、100–10000 米范围和进入/离开。位置监听会持续使用系统定位；精度覆盖边界时取消未完成的延时触发。启用后台位置权限前，不启动后台位置监听。首次读数只建立基线，不作为进入或离开事件。锁屏、权限、系统杀后台、定位或 Wi-Fi 关闭以及信号不佳都可能导致延迟、漏报或不可用，需要真机验证。

车辆检查应由用户在任务内容中明确要求读取并报告状态；无法读取或确认的情况应在结果中说明，不能假设车辆已上锁或车窗已关闭。操作其他 App 还取决于设备解锁、无障碍权限和目标 App 的实际状态。

## 预约拨号与来电交代

拨打任务选择日期与时间，默认取系统当前时钟作为选择器初值；语音时间必须能解析为明确的未来时间。保存时固定号码与所选 SIM 并登记精确闹钟。相同的时段在持久化认领后最多尝试一次。多个到点任务在有通话时最多等待两分钟，过期不补拨。AI 电话未准备、号码不可拨、SIM 不可用或通知权限缺失时如实标记失败。启动进程丢失后状态不明的任务不自动重拨；超过五分钟后再次打开会标记为未确认。系统确认发起拨号不等于接通或完成转告，通话结果以记录为准。重启后由开机广播尝试恢复；明确退出应用期间不执行。必须授权精确闹钟，设备省电及系统后台限制可能影响及时性。

来电交代可设置开始及结束时间，永久设置保留。语音识别仅作为待核对的输入，不会自行猜测拨号号码或模糊的时间。已存旧拨打任务只保留原有文字，不自动转换成电话预约，避免升级后意外拨出。
