# 用户可控短信自动登录（实验性）

关联 #606。设置 → 短信验证码登录默认关闭。用户一次性开启 Android RECEIVE_SMS 权限并配置可信服务/账户后，后续明确要求登录该 App 的本机主任务可以自动请求短信、填账户/验证码、点击最终登录及核验登录结果，不再逐次确认或重填匹配参数。#609 的旧版仅授权逐次填码；旧版许可不会迁移为自动提交许可，必须重新阅读设置中的说明并开启。

## 一次配置与授权

设置页可新增、编辑和删除本机可信配置。一个 App 配置一个账户；配置包括已安装 App 的包名、准确短信发送方、服务签名、账户号码及短信中的账户标识、原生账户框/验证码框/发送按钮/最终登录按钮的完整资源 ID，以及已登录页面的明确标志、准确文字和账户显示控件。保存配置即授权相应登录流程；Android 从已安装 App 自动取得签名证书摘要，不能由模型或配置表单伪造。签名变化后必须重新核实配置。

本版是通用的受控原生映射入口，尚未内置经真机验证的商业 App 映射。初次配置属于高级设置，需要已核实的页面规则；不会猜测按钮、用坐标替代缺失控件，或把配置错误归为登录成功。账户是本机保存的 4–11 位数字，短信账户标识必须与其对应。已有另一账户显示在配置的账户输入框时拒绝覆盖。

许可和配置使用 Android Keystore 的 AES-GCM 加密并原子保存，不写入聊天、工具参数、模型上下文或明文偏好。只保存用户明确配置的匹配规则及账户，绝不保存短信或验证码。损坏、解密失败及旧版本许可均按关闭处理。关闭、编辑或删除配置均改变授权版本，取消当前任务；再次开启不会恢复旧授权。最后一次原生动作和撤销共用锁，关闭返回后不能再开始旧许可的输入或登录点击；已交给 Android 的动作无法撤回。

## 自动任务链

1. 模型仅调用 `phone_sms_login(app)`。工具限用户明确要求登录对应 App 的本机 UI 主任务，不提供给子任务、无人值守、渠道、MCP 或只读检查。未知配置、App 签名不一致、短信权限缺失、应用访问禁用或资料身份不明时返回实际状态，交用户手工处理。
2. 全流程先开启私密观察保护。在准确的原生账户框中核对或填入已配置账户，不经剪贴板。注册带系统签名级 BROADCAST_SMS 发送权限约束的临时 SMS_RECEIVED 接收器，再对准确的请求验证码按钮点击一次；不读收件箱、不使用常驻接收器、不修改默认短信角色。
3. 在 90 秒的新短信窗口内，要求准确发送方、正文开头的 `【服务签名】` 或 `[服务签名]`、登录语义、对应账户标识，以及唯一明确标记的 4–8 位验证码。支付、转账、注册、改密、找回、绑定、歧义和过期短信拒绝。窗口只能消费一次，重复广播不能再次填码或提交。
4. 输入前再次核对签名、授权版本、App、主用户资料及准确账户框。对唯一验证码框调用 ACTION_SET_TEXT 一次；没有焦点、坐标或通用粘贴兜底。若 App 已自动提交，不再点击。否则只点击配置的、文字为“登录”等明确登录语义的最终原生按钮一次，不自动同意协议、处理支付、注册、账户恢复或风控。
5. 在本机等待实际登录结果。成功必须同时看到配置的已登录标志及对应账户，验证码框和登录按钮已经消失，原生树、窗口内容和本机 OCR 均没有残留验证码；连续两次观察满足条件才返回 logged_in。明确错误返回 login_failed；超时、OCR 不可用、身份/界面变化或缺少证据返回 login_unverified 等状态。输入被接受或点击成功从来不等于已经登录。
6. 核验成功后恢复原生文字读屏和普通控件操作，任务可以继续；不是把后续读屏全部禁止再声称登录完成。本次任务的图片、预览和通用系统命令继续留在本机，防止像素或旁路残留。任务内仅保留不可导出的短期验证码指纹，用于脱敏后续文字树、OCR、事件及动作提示中的同一验证码（含空格、连字符和全角变体），任务结束清零；不保存原码。未核验成功时保持观察保护并报告未完成，保留手工接管。

状态流程在 `SmsLoginAutomation`；规则和证据检查在 `SmsLoginProfile`、`SmsLoginMatcher`、`SmsLoginWindow`、`SmsLoginEvidence`；Android 广播及授权检查在 `AndroidSmsLogin`；准确控件输入和本机 OCR 在 `AndroidScreen`。设置使用 `SmsLoginSettings`。授权界面和目标教学事件仍受现有敏感 UI 保护，认证秘密通知在收件箱入库前被拒绝。

## 确切边界与待验证项

- Android 10+、主用户资料、原生单个验证码框及明确资源 ID。无资源 ID、WebView、分格验证码、工作资料/分身及不明确的页面映射不支持。没有可信已登录账户标志或 OCR 无法确认无残码时，不报告成功。
- 短信必须能安全匹配账户。服务完全不提供账户标识、发送方/服务不明确、账户不一致等场景不猜测，仍需手工处理。这里的回退是身份或系统能力不足，不是逐次授权版流程。
- RECEIVE_SMS 属 Android 危险且严格受限权限，安装器白名单、厂商 ROM 和分发渠道可能阻止授予；不会用 shell 绕过。见 [Android 权限文档](https://developer.android.com/reference/android/Manifest.permission#RECEIVE_SMS)。不依赖 Google Play 服务。
- SMS 发送时间按系统短信的一秒精度校验；延迟、时钟不一致、分段异常或超出窗口的短信可能拒绝。整个自动流程最长 180 秒。取消、权限/配置撤销或任务停止注销接收器，清理暂存码且不重试登录点击。
- 系统短信应用自身的存储、用户主动分享、任意同 UID 代码、沙箱命令和外部 MCP 不是本功能的数据隔离对象；提示词禁止通过这些路径绕过拒绝。本实现不是全局安全沙箱。Android 必须使用的临时不可变字符串无法原地清零，但不会主动记录或长期保存。
- 合成测试覆盖自动成功、App 自动提交、错服务/账户、支付、重复/过期短信、取消、关闭/删除配置、登录错误、没有成功证据、残留验证码和文字观察恢复。尚未使用真实账户、号码或短信，也未做真机商业 App 端到端验收。安装器授权、厂商短信广播/分段、配置映射、原生控件、OCR、证书变化及撤销时序仍需测试设备上的合成短信验证；编译和合成单测不等同于所有机型/App 已验证。
